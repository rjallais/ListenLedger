* Overview
ListenLedger is a Go web dashboard for managing a Spotify music collection and refreshing monthly listener counts. It runs PocketBase with embedded NATS and serves a Templ + Datastar UI.

* Features
- Albums, artists, and songs dashboards
- Add Song flow from =/songs= (modal posts to =/api/songs= and prepends the new row)
- On-demand refresh per artist with SSE updates
- Provider-aware scraping: local headless (go-rod), Browserless, ScrapingAnt, ScraperAPI, Apify
- Quota check endpoint at =/api/quota=
- CSV seed support from =Music - Sheet1.csv= and =Music - Sheet2.csv=

* Adding Songs
Open =/songs=, click =Add Song=, then submit song name, release, release year, and artist Spotify IDs (comma-separated).
The server validates each artist Spotify ID and infers artist names from Spotify before saving.

* Architecture
- =main.go= bootstraps PocketBase, embedded NATS, routes, and the worker
- =internal/handlers/= HTTP + SSE endpoints
- =internal/worker/= NATS consumer with pull-based per-provider goroutine pools (quota-aware shutdown)
- =internal/fetcher/= retries and orchestration
- =internal/spotify/= provider clients
- =pb_schema.json= schema export for collections

At least one provider must be configured, or keep local headless enabled.
Data is stored in =pb_data/= at the repo root by default; override with =PB_DATA_DIR=.

* Build and Run

* Development
- Templ: =go tool templ generate=
- Tailwind: =go tool gotailwind -i input.css -o static/styles.css=
- Data lives in =pb_data/=. Backups can be made via =cmd/safebackup=.

* CLI Utilities
- =cmd/update_listeners=: bulk refresh using go-rod with priority ordering.
  Example:
#+begin_src sh
GOEXPERIMENT=jsonv2 go run ./cmd/update_listeners --concurrency 5 --headless=true --limit 0
#+end_src
- =cmd/safebackup=: VACUUM INTO backup for SQLite.
#+begin_src sh
go run ./cmd/safebackup --db pb_data/data.db --out backups
#+end_src
- =cmd/backfill_song_artists=: dry-run-first backfill for songs with empty =artist_spotify_ids=. It uses existing artist records for exact matches, MusicBrainz recording credits as the primary collaborator source, and Deezer track contributors as a fallback when MusicBrainz cannot resolve the credit list cleanly. Optionally, supply TIDAL credentials to enable artist-name prefill as a secondary source for expanding ellipsis-truncated credit lists (e.g. "Artist, ...").
  TIDAL flags (all optional):
  - =--tidal-token=: bearer token for TIDAL OpenAPI (or set =TIDAL_TOKEN= env var)
  - =--tidal-client-id=: client ID for TIDAL client-credentials auth (or set =TIDAL_CLIENT_ID=)
  - =--tidal-client-secret=: client secret for TIDAL client-credentials auth (or set =TIDAL_CLIENT_SECRET=)
  When =--tidal-client-id= and =--tidal-client-secret= are set but no =--tidal-token= is given, the tool automatically obtains a bearer token via the OAuth client-credentials flow. TIDAL prefill works alongside MusicBrainz and Deezer in both dry-runs and =--apply= runs; other flags (=--limit=, =--apply=, =--min-confidence=) and output paths (=backfill_reports/=) are unchanged.
  Example:
#+begin_src sh
GOEXPERIMENT=jsonv2 go run ./cmd/backfill_song_artists --limit 25
cp -a pb_data /tmp/listenledger-pb-data-copy
GOEXPERIMENT=jsonv2 go run ./cmd/backfill_song_artists --data-dir /tmp/listenledger-pb-data-copy --limit 25
GOEXPERIMENT=jsonv2 go run ./cmd/backfill_song_artists --apply
# With TIDAL prefill:
TIDAL_CLIENT_ID=xxx TIDAL_CLIENT_SECRET=yyy GOEXPERIMENT=jsonv2 go run ./cmd/backfill_song_artists --limit 25
#+end_src
  Review the JSON audit report in =<data-dir>/backfill_reports/= and run =cmd/safebackup= before using =--apply=. Dry-runs now also emit a JSON + CSV review queue for the remaining manual cases in the same =backfill_reports/= directory. If the web app is running, stop it first or dry-run against a copied =pb_data/= directory. MusicBrainz lookups are paced and retried automatically for transient 429/5xx failures, and Deezer is used as a secondary source for collaborator discovery, so full dry-runs are slower but more reliable.

* Troubleshooting
- =encoding/json/v2= errors: ensure =GOEXPERIMENT=jsonv2=.
- Provider 401/403/429: verify tokens and quotas.
- Local headless errors: set =LOCAL_CHROME_PATH= or disable with =LOCAL_HEADLESS_ENABLED=false=.
