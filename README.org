* Overview
ListenLedger is a Go web dashboard for managing a Spotify music collection and refreshing monthly listener counts. It runs PocketBase with embedded NATS and serves a Templ + Datastar UI.

* Features
- Albums, artists, and songs dashboards
- Add Song flow from =/songs= (modal posts to =/api/songs= and prepends the new row)
- On-demand refresh per artist with SSE updates
- Provider-aware scraping: local headless (go-rod), Browserless, ScrapingAnt, ScraperAPI, Apify
- Quota check endpoint at =/api/quota=
- CSV seed support from =Music - Sheet1.csv= and =Music - Sheet2.csv=

* Adding Songs
Open =/songs=, click =Add Song=, then submit song name, release, release year, and artist Spotify IDs (comma-separated).
The server validates each artist Spotify ID and infers artist names from Spotify before saving.

* Architecture
- =main.go= bootstraps PocketBase, embedded NATS, routes, and the worker
- =internal/handlers/= HTTP + SSE endpoints
- =internal/worker/= NATS consumer with pull-based per-provider goroutine pools (quota-aware shutdown)
- =internal/fetcher/= retries and orchestration
- =internal/spotify/= provider clients
- =pb_schema.json= schema export for collections

* Development
- Templ: =go tool templ generate=
- CSS: =mise run build:css= (or =go run ./cmd/build=)
- Data lives in =pb_data/=. Backups can be made via =cmd/safebackup=.

* CLI Utilities
- =cmd/update_listeners=: bulk refresh using go-rod with priority ordering.
  Example:
#+begin_src sh
go run ./cmd/update_listeners --concurrency 5 --headless=true --limit 0
#+end_src
- =cmd/safebackup=: VACUUM INTO backup for SQLite.
#+begin_src sh
go run ./cmd/safebackup --db pb_data/data.db --out backups
#+end_src
- =cmd/backfill_song_artists=: dry-run-first backfill for songs with empty =artist_spotify_ids=. It uses existing artist records for exact matches, MusicBrainz recording credits as the primary collaborator source, and Deezer track contributors as a fallback when MusicBrainz cannot resolve the credit list cleanly. Optionally, supply TIDAL credentials to enable artist-name prefill as a secondary source for expanding ellipsis-truncated credit lists (e.g. "Artist, ...").
  TIDAL flags (all optional):
  - =--tidal-token=: bearer token for TIDAL OpenAPI (or set =TIDAL_TOKEN= env var)
  - =--tidal-client-id=: client ID for TIDAL client-credentials auth (or set =TIDAL_CLIENT_ID=)
  - =--tidal-client-secret=: client secret for TIDAL client-credentials auth (or set =TIDAL_CLIENT_SECRET=)
  When =--tidal-client-id= and =--tidal-client-secret= are set but no =--tidal-token= is given, the tool automatically obtains a bearer token via the OAuth client-credentials flow. TIDAL prefill works alongside MusicBrainz and Deezer in both dry-runs and =--apply= runs; other flags (=--limit=, =--apply=, =--min-confidence=) and output paths (=backfill_reports/=) are unchanged.
  Example:
#+begin_src sh
go run ./cmd/backfill_song_artists --limit 25
cp -a pb_data /tmp/listenledger-pb-data-copy
go run ./cmd/backfill_song_artists --data-dir /tmp/listenledger-pb-data-copy --limit 25
go run ./cmd/backfill_song_artists --apply
# With TIDAL prefill:
TIDAL_CLIENT_ID=xxx TIDAL_CLIENT_SECRET=yyy go run ./cmd/backfill_song_artists --limit 25
#+end_src
- =cmd/backfill_song_metadata=: fills missing song metadata (album, release date, release year, release type) from TIDAL search, pre-filled by the =release_type= labels the PB→ledger migration dropped, and records =SongMetadataEnriched= events in the authoritative store. Dry-run by default (emits a JSON report in =<data-dir>/backfill_reports/=); =--apply= appends the events. Lookups are paced and retried; a silent 429 is TIDAL's quota window failing fast, so rerun later to pick up the remainder.
  Example:
  #+begin_src sh
  # 1. Dry-run and review the JSON report
  fnox exec -- env LISTENLEDGER_EVENT_STORE=jetstream go run ./cmd/backfill_song_metadata --data-dir pb_data

  # 2. Apply after review (stop the app first; --live-ok only acknowledges the live dir of a stopped app)
  fnox exec -- env LISTENLEDGER_EVENT_STORE=jetstream go run ./cmd/backfill_song_metadata --data-dir pb_data --apply --live-ok
  #+end_src
- =cmd/tidal_sync=: synchronizes favorite tracks from your TIDAL account using OAuth 2.0 PKCE. Built in the event-sourced CQRS architecture, observations are captured in immutable =tidalsync= event streams in the authoritative event store (=LISTENLEDGER_EVENT_STORE=), differences are reconciled into proposal reports, and approved proposals are applied to the catalog read model and song event streams. Secrets (=TIDAL_CLIENT_ID=, =TIDAL_CLIENT_SECRET=) are managed with FNOX via the tracked =fnox.toml=; the rotating =TIDAL_REFRESH_TOKEN= is stored in the global FNOX config (=~/.config/fnox/config.toml=) so refreshes never rewrite the tracked file.
  Example:
#+begin_src sh
# 1. Login once to link your TIDAL account and store the refresh token in FNOX
fnox exec -- go run ./cmd/tidal_sync login

# 2. Plan synchronization (dry-run default; emits JSON and CSV reports in backfill_reports/)
fnox exec -- env LISTENLEDGER_EVENT_STORE=jetstream go run ./cmd/tidal_sync plan --country BR

# 3. Apply approved proposals (stop the app first; --live-ok only acknowledges the live dir of a stopped app)
fnox exec -- env LISTENLEDGER_EVENT_STORE=jetstream go run ./cmd/tidal_sync apply --approve-all-above 0.90 --live-ok
#+end_src
  Backfill safety: review the JSON report in =backfill_reports/= and run =cmd/safebackup= before using =--apply=. The sync and backfill tools boot an embedded NATS server on the data directory, and a second server on a live store corrupts it. Stop the web app first: =--live-ok= only acknowledges that the target is the live directory of a stopped app. Alternatively, point =--data-dir= at a backup copy.

* Troubleshooting
- =encoding/json/v2= is stable in Go 1.27; no experiment flag is required.
- Provider 401/403/429: verify tokens and quotas.
- Local headless errors: set =LOCAL_CHROME_PATH= or disable with =LOCAL_HEADLESS_ENABLED=false=.
