* Overview
ListenLedger is a Go web dashboard for managing a Spotify music collection and refreshing monthly listener counts. It runs PocketBase with embedded NATS and serves a Templ + Datastar UI.

* Features
- Albums, artists, and songs dashboards
- Add Song flow from =/songs= (modal posts to =/api/songs= and prepends the new row)
- On-demand refresh per artist with SSE updates
- Provider-aware scraping: local headless (chromedp), Browserless, ScrapingAnt, ScraperAPI, Apify
- Quota check endpoint at =/api/quota=
- CSV seed support from =Music - Sheet1.csv= and =Music - Sheet2.csv=

* Adding Songs
Open =/songs=, click =Add Song=, then submit song name, release, release year, and artist Spotify IDs (comma-separated).
The server validates each artist Spotify ID and infers artist names from Spotify before saving.

* Architecture
- =main.go= bootstraps PocketBase, embedded NATS, routes, and the worker
- =internal/handlers/= HTTP + SSE endpoints
- =internal/worker/= NATS consumer with pull-based per-provider goroutine pools (quota-aware shutdown)
- =internal/fetcher/= retries and orchestration
- =internal/spotify/= provider clients
- =pb_schema.json= schema export for collections

* Configuration
Set env vars (via =mise= or your shell):

#+begin_src toml
[env]
PROJECT_NAME = "ListenLedger"
BROWSERLESS_TOKEN = "your_browserless_token"
SCRAPINGANT_TOKEN = "your_scrapingant_token"
SCRAPERAPI_TOKEN = "your_scraperapi_token"
APIFY_TOKEN = "your_apify_token"
# Optional overrides
BROWSERLESS_ENDPOINT = "https://production-sfo.browserless.io/chromium/bql"
SCRAPINGANT_ENDPOINT = "https://api.scrapingant.com/v2/general"
SCRAPERAPI_ENDPOINT = "https://api.scraperapi.com"
SCRAPERAPI_CONCURRENCY = "5"
SCRAPERAPI_WAIT_FOR_SELECTOR = "span"
LOCAL_HEADLESS_ENABLED = "true"
LOCAL_CHROME_PATH = "C:\\Path\\To\\chrome.exe"
LOCAL_CONCURRENCY = "8"
MAX_CONCURRENCY = "1"
MAX_RETRIES = "2"
LOG_SUCCESSFUL_FETCHES = "false"
PB_DATA_DIR = "pb_data"
#+end_src

At least one provider must be configured, or keep local headless enabled.
Data is stored in =pb_data/= at the repo root by default; override with =PB_DATA_DIR=.

* Build and Run
#+begin_src sh
GOEXPERIMENT=jsonv2 go run .

# or build
GOEXPERIMENT=jsonv2 go build -o ListenLedger .
GOEXPERIMENT=jsonv2 ./ListenLedger
#+end_src

The web UI is served on PocketBase's default port (usually http://127.0.0.1:8090). Admin UI: =/_/=.

Using =mise=:
#+begin_src sh
mise run build
mise run run
#+end_src

* Development
- Templ: =go tool templ generate=
- Tailwind: =go tool gotailwind -i input.css -o static/styles.css=
- Data lives in =pb_data/=. Backups can be made via =cmd/safebackup=.

* CLI Utilities
- =cmd/update_listeners=: bulk refresh using chromedp with priority ordering.
  Example:
#+begin_src sh
GOEXPERIMENT=jsonv2 go run ./cmd/update_listeners --concurrency 5 --headless=true --limit 0
#+end_src
- =cmd/safebackup=: VACUUM INTO backup for SQLite.
#+begin_src sh
go run ./cmd/safebackup --db pb_data/data.db --out backups
#+end_src

* Troubleshooting
- =encoding/json/v2= errors: ensure =GOEXPERIMENT=jsonv2=.
- Provider 401/403/429: verify tokens and quotas.
- Local headless errors: set =LOCAL_CHROME_PATH= or disable with =LOCAL_HEADLESS_ENABLED=false=.
